# AI Yukkuri Studio

動画とシナリオからゆっくり実況動画を自動生成・編集するWebアプリ。現在は **開発指示書 Ver.2.0 の画面構成（ログイン・キャラクター管理・台本作成）** まで。AIはモック。

## 起動手順

```bash
# 1. DB (PostgreSQL)
docker compose up -d

# 2. バックエンド (Python 3.11+ / FFmpeg が必要)
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
# 設定を変えたい場合は環境変数で渡す（.env は読み込まれない）。例: $env:MAX_UPLOAD_MB="4096"
alembic upgrade head            # DBのテーブルを作る/更新する（初回と、スキーマが変わったとき）
uvicorn app.main:app --reload   # http://localhost:8000/docs でAPI確認

# 3. フロントエンド (Node 20+)
cd ../frontend
npm install
npm run dev                     # http://localhost:5173 を開く（このアドレス経由で /api が中継され、ログインのCookieが使える）
```

DBが最新でないとバックエンドは起動時にエラーで止まります（`alembic upgrade head` を促すメッセージが出ます）。

テスト（外部サービス不要、SQLiteで動作）: `cd backend && pytest`
型チェック＋ビルド: `cd frontend && npm run build`

## ログインとデータの分離
- メールアドレス＋パスワードで登録/ログイン。パスワードは argon2 でハッシュ化して保存。
- ログイン状態は HttpOnly の Cookie（`SameSite=Lax`）。サーバー側にセッションを持ち（トークンはハッシュで保存）、ログアウトで無効化、既定14日で失効。
- プロジェクト・台本・キャラクター・音声/画像・生成ジョブは、すべてユーザーごとに分離。**他人のデータは「存在しない」(404)として扱う**。
- ログイン失敗が続くと一時的に拒否（既定: 10分間に5回）。**メモリ上の簡易実装**のため、サーバー再起動でリセットされ、複数台構成では共有されない。
- 設定（環境変数）: `ALLOW_REGISTRATION`（`false`で新規登録を停止）、`SESSION_DAYS`、`COOKIE_SECURE`（**HTTPSで公開するときは `true`**）、`LOGIN_MAX_FAILURES`、`LOGIN_WINDOW_SECONDS`、`CORS_ORIGINS`。

## キャラクターの扱い（仕様の決定事項）
- **キャラクター管理（ライブラリ）**: ユーザーごとに作成・保管。どのプロジェクトからでも使える。
- **プロジェクトへ追加した時点の内容が、そのプロジェクト用に「コピー」される。** 以降、台本作成画面での編集がそのプロジェクトでは優先される。
- キャラクター管理での編集・削除は、**追加済みのコピーには影響しない**。次にプロジェクトへ追加するときから反映される（最新を取り込み直したいときは、プロジェクトから外して再度追加。セリフは残り、話者名で自動的に結びつき直す）。
- 同じキャラクターを同じプロジェクトに二重には追加できない。プロジェクト内・ライブラリ内ともに、キャラクター名は重複不可（台本の話者名と名前で対応づけるため）。

## 台本の書式
```
[霊夢]
こんにちは！
今日も実況していきます
[魔理沙]
よろしくな！
```
- `[話者名]` の次の行から、次の `[話者名]` までが、その話者のセリフ（**1行=1セリフ**）。空行と `#` で始まる行は無視。
- `[話者名]` が1つもない台本に限り、旧書式「話者: セリフ」も読む（`[話者]` がある台本では、セリフ中の「注意: …」を話者と誤認しないため使わない）。
- 台本にあるがプロジェクトに未追加の話者は、**キャラクターを自動作成せず、警告を表示**する（音声・立ち絵は追加するまで作れない）。ライブラリに同名がいれば、その場で追加できる。
- 同時会話は書式ではなく、画面上でセリフを複数選択して「同時にする」で指定する（`simultaneous_group`）。

## AIエンジン（プロバイダー）の切り替え
音声・画像・LLM はそれぞれ `backend/app/providers/` のインターフェース（`base.py`）の裏にあり、
現在は全て `mock`（仮の音・仮の絵・キーワード判定）。環境変数で選ぶ:
`VOICE_PROVIDER` / `IMAGE_PROVIDER` / `LLM_PROVIDER`（既定はすべて `mock`）。
本物（VOICEVOX等）を追加するときは、インターフェースを満たすクラスを作り、`registry.py` の辞書に1行足す。
