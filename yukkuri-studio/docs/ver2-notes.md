# Ver.2.0 変更メモ（影響範囲・仕様との差異・既知の制約）

## 仕様書から意図的に変えた点
| 仕様 | 実装 | 理由 |
|---|---|---|
| キャラクターとプロジェクトを `project_characters`（紐づけ表）でつなぐ想定 | `characters` 表に「ライブラリ（`project_id` 空）」と「プロジェクト用のコピー（`project_id` あり、`source_character_id` で元を記録）」を同居 | 「編集画面の状態を優先し、管理画面の編集は次回の制作から反映」という決定は、追加時点のコピーでないと実現できないため。紐づけ表は不要になった |
| 時間の列名 `duration` など | `*_ms`（整数ミリ秒） | 単位を明示するため |
| `character_assets` と `assets` を別表 | `assets` に統合（`character_id` / `dialogue_id` のどちらかを持つ） | 画像・音声サンプル・セリフ音声を同じ仕組みで配信・所有者確認するため |
| ログイン失敗の制限（仕様の細目なし） | メモリ上の簡易制限 | 再起動で消える・複数台で共有されない。本番の複数台構成ではRedis等へ置き換える |

## 仕様が決めていなかったので、こう判断した点
- 台本の1行=1セリフ（`[話者]` の下の各行）。複数行を1つのセリフにまとめたい場合の書式は未定義。
- プロジェクト作成時に、空の「台本1」を自動で1つ作る（作成直後から書き始められるように）。
- キャラクターのコピー元をライブラリから削除しても、コピー・画像・セリフは残る（コピー側の `source_character_id` が空になるだけ）。
- コピーを「プロジェクトから外す」と、セリフは残り話者が未登録になる（`speaker_name` は残る）。再度追加すると、話者名で自動的に結びつく。
- 未登録の話者は「警告」で、台本の分割や保存は止めない（音声・立ち絵の生成だけが、追加するまでできない）。
- セリフ更新APIは `PUT` だが、送った項目だけを更新する（部分更新）。
- 他人のデータへのアクセスは 403 ではなく 404（IDの存在を推測させないため）。

## 影響範囲の整理（実装時に確認した点）
- 全APIに所有者チェック。音声・画像の配信、ジョブの参照・再実行、動画のストリーミングも対象。ジョブは実行時にも対象の所有者を再確認する。
- ジョブ: `user_id` 必須、`project_id` は任意（キャラクター単体の画像・音声サンプル生成はプロジェクトに属さない）。
- 外部キー: プロジェクト削除時にジョブ等が残ると PostgreSQL では失敗する（SQLiteは既定で外部キーを検査しないため、Phase 2のテストでは見逃していた）。`ON DELETE CASCADE` を付け、テストDBも外部キー検査を有効化した。
- ファイルの置き場所: プロジェクト用のコピーの画像は `<project_id>/characters/...`（プロジェクト削除でまとめて消える）、ライブラリの画像は `characters/<id>/...`。
- フロントエンド: ログイン切れ（401）を検知したらログイン画面へ戻す。ジョブの進捗取得中に切れた場合は、その表示が「失敗」になる。

## 未確認のこと（実機で確認が必要）
- PostgreSQL 上での `alembic upgrade head`、およびモデルとマイグレーションの一致（列名の突き合わせは静的に確認済み。型・制約の細部は未確認）。
- `pytest` の全テスト（認証・所有者チェック・コピー方式・生成など）。
- `npm run build` と、各画面の表示・操作。

## Phase 3 の範囲と判断
**仕様の食い違い**: 旧仕様(v1)のPhase 3は「動画・シナリオ同期(動画解析)」、Ver.2.0のPhase 3は「シナリオ管理」で、後者はすでにほぼ実装済み。
そのため、Phase 3 では「**セリフのタイミング自動配置と、字幕・立ち絵・音声の配置データ**」を実装した(Ver.2.0 で定義された `timeline_items` を使う)。動画の解析・話者識別は、元動画のアップロードが Phase 4 に移ったため、Phase 4 以降とした。

**判断した点(仕様に無かったので)**:
- セリフ間の間隔の初期値は0.3秒(画面で変更可)。音声が未生成のセリフの長さは「1文字0.17秒、最低0.8秒」で見積もり、警告を出す。
- 時間を手動で指定したセリフは `timing_locked` になり、自動配置で動かさない(「手動指定の時間も振り直す」で解除)。手動指定は開始・終了を必ず両方いっしょに送る。
- 時間の重なりは許可(同時会話のため)。同時会話は、グループの最初のセリフと同じ開始時間に置く。
- 項目の位置は画面に対する割合(0〜1)。立ち絵の初期位置は、プロジェクトのキャラクターを左から均等に並べた x、y=0.6。字幕は (0.5, 0.9)。再配置しても、ユーザーが変えた位置・拡大率・音量は残す。
- 音声の再生成などで長さが変わったセリフは「ずれ」と表示するだけで、自動では動かさない(手動調整を勝手に壊さないため)。

**未確認**: PostgreSQL での `0002` の適用、`tests/test_timeline.py`、`npm run build`、画面の表示。

## Phase 4 の範囲と判断
**範囲**: 仕様書4-6(動画編集画面)の、左(プレビュー・タイムライン)/右(音声・画像・字幕タブ)の2カラム、保存・編集履歴・Undo/Redo、部分再生成。
元動画アップロードは Phase 2 実装のまま使う。MP4への書き出しは Phase 5。

**判断した点(仕様に無かった・曖昧だったので)**:
- **編集の単位**: セリフ(dialogue_id)に、音声・立ち絵・字幕の3項目(`timeline_items`)が付く。キャラクターのレーンのブロック=セリフ全体(動かすと項目が連動)、字幕レーンのブロック=字幕だけ。画像タブ・字幕タブの「表示時間」は、その項目だけの時間。
- **連動のルール**: セリフを動かしても、すでに個別に時間を変えた項目(`times_edited`)は動かさない(手動の調整を壊さないため)。「すべて振り直す」でその印を外して振り直す。
- **表情の変更はセリフの感情を変えない**(感情を変えると音声が古くなるため)。立ち絵の表情は項目ごとの指定(空なら感情に従う)。画像が無い表情は、近い画像で代用して表示し、生成ボタンを出す。
- **字幕テキストの変更も、セリフ本文を変えない**(音声が古くならない)。項目ごとの上書きとして保存し、「セリフ本文に戻す」で戻せる。
- **再生速度**: 速度を変えると音声ブロックの終わりが自動で動く(2倍速なら半分)。セリフ全体の長さは動かさない。
- **音量**: 0〜200%で保存。ブラウザの制約でプレビューは100%まで。書き出し(Phase 5)で反映する。
- **同時字幕の重なり回避**: プレビューでは、位置がほぼ同じ字幕を上へずらして並べる。保存される位置は変えない。
- **元動画の音**: プレビューでは既定で鳴らす(切り替え可)。書き出し時の扱いは Phase 5 で決める必要がある。
- **履歴**: 1回の編集で影響を受けたセリフの「時間+全項目」を丸ごと記録し、元に戻す=編集前の記録で上書き。対象は項目の編集・セリフの時間変更・自動配置。プロジェクトごとに100件まで。台本を作り直してセリフが無くなった履歴は戻せない(409)。
- **音声の再生成**は履歴の対象外(生成物は元に戻せない)。再生成で長さが変わると「ずれ」が出るので、「この音声の長さに合わせる」で直す(このセリフの時間は手動指定扱いになる)。
- 編集は1操作ごとにサーバーへ保存(「保存」ボタンは無く、自動保存)。

**既知の制約**: 再生中に再生ヘッドが画面外へ出ても、自動ではスクロールしない。スマホ幅のタッチ操作は未調整。プレビューの再生は、ブラウザの自動再生制限などで音が出ない場合がある(その場合も映像と時間は進む)。

**未確認**: PostgreSQL での `0003`、`tests/test_timeline_edit.py`、`npm run build`、ブラウザでの再生・ドラッグ操作(音と映像の同期の体感を含む)。

## Phase 5 の範囲と判断
**範囲**: 編集結果のMP4への合成(FFmpeg)、レンダリング進捗の表示、ダウンロード。API は仕様書の `POST /render`、`GET /render-status`、`GET /download`。

**方式**: 立ち絵と字幕は、「表示の組み合わせが変わる時刻」で区切った区間ごとに、1枚の透明PNGへ合成(Pillow)し、それを1本の重ね映像としてFFmpegで元動画(または黒い背景)の上に重ねる。セリフの音声は、開始位置・速度・音量を反映して混ぜ、元動画の音も加える。
こうすると、セリフが何百件あってもFFmpegのコマンドが大きくならない(Windowsのコマンド長の制限に掛からない)。

**判断した点(仕様に無かった・曖昧だったので)**:
- **書き出す単位は「台本1つ」**(プロジェクトに複数の台本があるため)。省略すると最初の台本。
- **出力サイズ**: 元動画があればその縦横比を保つ(既定は元動画と同じ。480/720/1080pを選べる)。元動画が無ければ黒い背景の16:9(既定1080p)。元動画より字幕・音声が長ければ、最後の画面を保つ。
- **見た目の規則はプレビューと同じ**: 立ち絵の高さ=画面の高さ×0.6×拡大率、字幕の文字サイズ=設定値×画面の高さ÷1080、同時字幕は1.4行ぶん上へずらす。
- **音声の混ぜ方**: 元動画の音を含めるかは、画面のチェックで選ぶ(既定は含める。プレビューと同じ設定)。音量は0〜200%を反映(プレビューでは100%まで)。混ぜた結果が割れないよう、リミッターを掛ける。常に音声トラックを付ける(無音でも)。
- **書き出しの結果は最新の1つだけ残す**(新しい書き出しが成功したら、古いファイルを消す)。ストレージの無駄遣いを避けるため。
- **画像が無い・読めない立ち絵は、プレビューと同じ仮の枠で書き出し、警告を出す**(書き出し自体は止めない)。音声が無いセリフは無音、時間が未配置のセリフは含めない(どちらも警告)。
- **モック画像をSVGからPNGへ変更**: 書き出しで画像を読むのにPillow/FFmpegが必要で、SVGは環境によって読めないため。以前に作ったSVGの画像は書き出しに使えない(警告を出し、画像の再生成を案内する)。実AIの画像(PNG/JPEG/WebP)はそのまま使える。
- 書き出しの設定(出力サイズなど)はジョブに保存する。「もう一度試す」でも同じ設定で再実行される。

**既知の制約**: 書き出しの途中キャンセルは未対応。書き出し中にサーバーを再起動すると、そのジョブは失敗扱い(再実行できる)になる。複数ユーザーが同時に書き出すと、サーバーのCPUを取り合う(今は専用の順番待ちの仕組みは無い)。書き出し後に編集した内容は含まれない(再度書き出す)。ブラウザのプレビューと書き出し結果は、文字の描画エンジンが違うため、字幕の折り返し位置などが少し違うことがある。

**未確認**: PostgreSQLでの `0004`、`tests/test_render_api.py`、`npm run build`、Windows上の日本語フォントの自動検出と書き出し、ブラウザでの書き出し操作と進捗表示。
